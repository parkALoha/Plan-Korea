## 🔴 `20260827061500_e3_read_only_covers_storage.sql` — **ช่องยังเปิดอยู่จนกว่าจะรัน**

**ทำอะไร:** ปิดช่องที่ P2 พบ — `read-only mode` ผูก trigger ด้วย `… on public.%I`
→ **ครอบเฉพาะ schema `public`** แต่ไฟล์ตั๋วอยู่ใน `storage.objects` (schema `storage`)
→ ระหว่างโหมดอ่านอย่างเดียว ผู้ใช้ยัง **อัปโหลดและ *ลบ* ไฟล์ตั๋วได้**

🎯 **ตัวที่เจ็บคือ `delete`** — ลบตอน cutover (`E7`) = ไฟล์แนบหายถาวรตอนฐานกำลังถูกคัดลอก **กู้ไม่ได้**
· อัปโหลดตอน cutover = ไฟล์กำพร้า ซึ่งกู้ได้

⚠️ **ต่างจากอีก 2 ไฟล์ในโฟลเดอร์นี้: ตัวนี้ *ไม่ได้* รอใครตัดสิน** — มันรอแค่คนรัน
· ปุ่มที่ P2 ปิดใน `BookingEditModal` **เป็นด่านเดียวจริง ๆ สำหรับอัปโหลด/ลบไฟล์ตอนนี้**
  ซึ่งเป็นสภาพชั่วคราวที่ไม่ควรอยู่นาน
· หลังรันแล้ว เคส *"migration ในทรี กับที่ฐานรันไปแล้ว ต้องเป็นชุดเดียวกัน"* ใน `rlsMatrix`
  **จะบอกเองว่าตรงกันแล้วหรือยัง — ไม่ต้องเชื่อใคร**
· 🔴 ด่านยืนยันในไฟล์ตรวจได้แค่ว่า **policy อ้าง `write_is_blocked` จริง**
  **ตรวจไม่ได้ว่าผู้ใช้จริงอัปโหลดไม่ได้จริง** — ต้องมีเคสยิงผ่าน storage-api ใน `rlsMatrix.test.ts` (ยังไม่มี)
