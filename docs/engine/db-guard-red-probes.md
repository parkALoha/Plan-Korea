# 🔴 พิสูจน์ว่าด่านฝั่งฐานแดงเป็น — วิธียิงและผลที่วัดได้

**เจ้าของ:** P1-Lead · 4 ก.ย. 2026

> 🎯 **ทีมมีเกณฑ์ของตัวเองว่า *"ด่านที่ยังไม่พิสูจน์ว่าแดงเป็น ไม่ใช่ด่าน"***
> และ *"ถามว่า **ด่านนี้เคยแดงจริงไหม** ไม่ใช่ **วันนี้เขียวไหม**"*
> · 🔴 **`app.assert_cache_lockdown()` ถูก *พิน* ว่ามีอยู่ (`schemaPins`) และถูก *เรียก* ใน `cache-warm.yml`
>   แต่ไม่เคยมีใครพิสูจน์ว่ามันจับการละเมิดได้จริง** — ไฟล์นี้ปิดช่องนั้น

---

## ⚠️ ทำไมด่านฝั่งฐานพิสูจน์ยากกว่าด่านฝั่งโค้ด
```
ด่านฝั่งโค้ด   มัลแตนต์ = แก้ไฟล์ → รันเทสต์ → คืนไฟล์        ไม่มีผลค้าง
ด่านฝั่งฐาน    มัลแตนต์ = **แก้ข้อมูล/สิทธิ์บนฐานที่ใช้ร่วมกัน**   ผลค้างได้ถ้าพลาด
```
🔴 ⇒ **ต้องยิงในทรานแซกชันที่ `rollback` เสมอ และต้องวัดหลังจบว่าไม่มีอะไรหลงเหลือ**
· 🔴 **และต้องเลือกมัลแตนต์ที่เบาที่สุดที่ยังสร้างเงื่อนไขได้จริง** —
  ที่นี่เลือก *แถวข้อมูลปลอมหนึ่งแถว* **ไม่ใช่การแก้ `grant`** ทั้งที่ด่านตรวจ `grant` ด้วย
  · เหตุผล: grant ที่ค้างเพราะ rollback ไม่ทำงาน = **ช่องความปลอดภัยจริง** · แถวข้อมูลที่ค้าง = ขยะที่ลบได้
  · ⚠️ **ข้อ ①–⑤ (ฝั่งสิทธิ์) จึงยัง *ไม่ได้* ถูกพิสูจน์ว่าแดงเป็น** — จดไว้ตรง ๆ ไม่กลบ

## ✅ ท่าที่ใช้ — ทิศบวกต้องมาก่อน ไม่งั้นทิศแดงไม่มีความหมาย
```sql
begin;
create temp table probe(step text, result text);
do $probe$
begin
  -- ① ทิศบวก: สภาพจริงวันนี้ต้องผ่าน
  begin perform public.assert_cache_lockdown();
        insert into probe values ('บวก','ผ่าน');
  exception when others then insert into probe values ('บวก','🔴 '||SQLERRM); end;

  -- ② ทิศแดง: สร้างการละเมิดที่เบาที่สุด
  insert into public.place_details_cache (maps_query, fetched_at)
  values ('__redprobe__ไม่มีในคลัง__', now());

  begin perform public.assert_cache_lockdown();
        insert into probe values ('แดง','🔴 ไม่ raise — ด่านมองไม่เห็นการละเมิด');
  exception when others then insert into probe values ('แดง','แดงถูกต้อง: '||left(SQLERRM,90)); end;
end $probe$;
select step, result from probe order by step;
rollback;
```
**แล้ววัดหลังจบเสมอ:** จำนวนแถวกลับเท่าเดิม · `where maps_query like '%redprobe%'` ต้องได้ `0` · ด่านยังผ่าน

## 📌 ผลที่วัดได้ 4 ก.ย. 2026 (engine-dev)
| ทิศ | ผล |
|---|---|
| ① บวก — สภาพจริง | **ผ่าน ไม่ raise** |
| ② แดง — คีย์นอกคลัง | **แดงถูกต้อง** · ข้อความระบุตารางและยกตัวอย่างคีย์ที่ผิดมาด้วย |
| หลัง `rollback` | `place_details_cache` 174 · `place_photo_cache` 173 · แถวโพรบเหลือ **0** · ด่านยังผ่าน |

· ✅ **ข้อความ error ระบุ *ตาราง* + *จำนวน* + *ตัวอย่างคีย์***
  ⇒ คนที่เจอมันแดงจะรู้ทันทีว่าต้องไปลบอะไร **ไม่ใช่แค่รู้ว่ามีอะไรผิด**
  🎯 รูปเดียวกับข้อความ fallback ของ `/today` ที่กันผมไม่ให้รายงานบั๊กที่ไม่มีอยู่ —
  ***ข้อความที่ระบุสาเหตุคือด่านกันการวินิจฉัยผิด ไม่ใช่ของตกแต่ง***

## 🔴 ข้อจำกัดของไฟล์นี้
- **ไม่ใช่ด่านอัตโนมัติ** — มันคือวิธียิงด้วยมือ · ทำเป็นเทสต์อัตโนมัติได้ยากเพราะต้องเขียนฐานจริง
- **ครอบเฉพาะข้อ ⑥** (คีย์ต้องอยู่ในคลัง) · **ข้อ ①–⑤ ฝั่งสิทธิ์ยังไม่ถูกพิสูจน์**
- ผลเป็นของ **สภาพฐาน ณ วันนั้น** — รันซ้ำได้ทุกเมื่อ และควรรันซ้ำเมื่อมีคนแก้ตัวด่าน
