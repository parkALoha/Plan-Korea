### 3.1 ✅ **นิ่งแล้ว · ยิงพิสูจน์แล้ว** — ทิศแดงต้องยิงใน `git worktree` แยก

> 🔴 **ทิศแดงต้องยิงผ่าน *เส้นทางจริง* — และยิงใน `git worktree` แยก ไม่ใช่ทรีร่วม**
>
> ป้อนสตริงละเมิดเข้าตัวจับ พิสูจน์ว่า **ตัวจับ** ทำงาน · ไม่ได้พิสูจน์ว่า *เดินไฟล์ → อ่าน → ตัดคอมเมนต์ → จับ* ต่อกันติด
> — **ด่านที่ตัวจับดีแต่เดินไฟล์ไม่เจอ เขียวเหมือนด่านที่ผ่านทุกประการ**
>
> ```bash
> SHA=$(git rev-parse HEAD); W=<scratchpad>/probe
> git worktree add --detach "$W" "$SHA" && ln -s <ทรีจริง>/node_modules "$W/node_modules"
> cd "$W" && npx vitest run <ไฟล์ด่าน>              # ① ต้องเขียวก่อน
> printf '<ของละเมิด>' > <พาธในโซนสแกน> && ls <พาธ>   # ls = หลักฐานว่าของถูกวางจริง
> npx vitest run <ไฟล์ด่าน>                          # ② ต้องแดง และข้อความต้องระบุพาธที่วาง
> cd <ทรีจริง> && git worktree remove --force "$W" && git worktree prune
> ```
> · ⚠️ **"ต้องแดง" ไม่พอ ต้อง *แดงแล้วเรียกชื่อไฟล์ที่เราวางถูก*** — ไม่งั้นแยกไม่ออกจากด่านที่แดงด้วยเหตุอื่น
> · 🔴 **ต้องเขียวรอบแรกก่อนวางของละเมิด** — ด่านที่แดงอยู่แล้วด้วยเหตุอื่น ทำให้รอบสองไม่มีความหมาย
> · ✅ **`ln -s node_modules` พอสำหรับ `vitest`** — `cp -al` 508M เป็นราคาของ `build`/`tsc` เท่านั้น
> · 🎯 **ไม่มีขั้น "ลบไฟล์โพรบ" ให้ข้าม** — `worktree remove --force` พาไปเอง
>   **ท่าทรีร่วมมีขั้นนั้น และขั้นที่ข้ามได้จะถูกข้ามสักวัน** (รูปเดียวกับที่ `push` จาก worktree ชนะท่า `$SHA`)
> · **ข้อยกเว้นเดียว:** ด่านที่ต้องการของที่ `build` แล้ว → ยิงบนทรีร่วมได้ **แต่เป็นทางรอง**
>   *ราคาบนทรีร่วมเป็นภาระของคนอื่น · ราคาของ worktree เป็นภาระของตัวเอง*

**ที่มา:** P7 ร่าง · ฉบับแรกเขียนเฉพาะท่าทรีร่วม ซึ่ง **P4 ไม่ได้ใช้** (เขายิง 7 ใบใน worktree)
· P7 **ไม่รับข้อเท็จจริงนั้นมาเขียนต่อ — ยิงเองที่หมุด `0b7a26d`** แล้วพบว่าราคาที่ตัวเองกลัวเป็นของ `build` ไม่ใช่ของ `vitest`

### 3.3 ✅ **นิ่ง** — `HEAD` กับ sha ของคนอื่น ใช้คนละงาน (P8 เสนอ · เกิดจริง 4 รอบคืนนี้)

> **จดสถานะปัจจุบันของไฟล์ → อ่านจาก `HEAD` เสมอ**
> **ยืนยันผลที่คนอื่นวัดไว้ → ปักหมุดจาก sha ที่เขารายงาน**
>
> เส้นแบ่ง: *"งานนี้กำลังตอบคำถามอะไร"* — ถ้าตอบ *"ตอนนี้ไฟล์เป็นยังไง"* ใช้ `HEAD` ·
> ถ้าตอบ *"ผลที่เขาวัดตอนนั้นถูกไหม"* ใช้ sha ของเขา
> 🔴 **การรับ sha มาในข้อความแล้วใช้เป็นฐานความจริงของสถานะปัจจุบัน คือจุดที่พลาดง่ายที่สุด**
> เพราะ **sha *ดูเหมือนความแม่นยำ*** — เจาะจงกว่า `HEAD` เลยรู้สึกปลอดภัยกว่า **ทั้งที่เป็นค่าที่ตายแล้ว**
>
> 🔴 **และขยาย `§3.3` ที่มีอยู่ (*"ห้ามเขียน sha ลงในประกาศ"*) ให้ครอบ *ประกาศหลังทำ* ด้วย**
> ข้อเดิมเขียนไว้กันการประกาศ**ก่อน**วัด · รูปเดียวกันกัดตอนประกาศ**หลัง**ทำ:
> P1 ใส่ sha ในทุกข้อความรายงาน → P8 ยึดตาม sha นั้น → P1 commit ต่อ → **บันทึกล้าทันที**

**หลักฐาน — เกิดจริง 4 รอบติดกันคืนนี้ กับด่าน `E2-AC8`:**
```
รอบ 1  P8 จด "3 ทาง"   → P1 ปิด B5      → ล้า
รอบ 2  P8 จด "5 ทาง"   → P1 ปิด B7      → ล้า
รอบ 3  P8 จด "5 ทาง"   → P1 ปิด B7      → ล้า
รอบ 4  P8 เช็ค HEAD ถูก → P1 ปิด B10/B11 → ล้า
```
🎯 **รอบ 4 คือหลักฐานที่สำคัญที่สุด: P8 ทำถูกทุกขั้นตามกติกาใหม่แล้วยังล้า**
· **วิธีหยุดคือคนที่ *ขยับ* หยุด ไม่ใช่คนที่ *จด* ตามให้ทัน** — ไม่มีวินัยฝั่งผู้จดข้อไหนแก้ได้ ถ้าของที่ถูกจดยังเดิน

### 3.5 ✅ **นิ่ง** — เส้นคู่: รับไฟเขียวจากเพื่อนไม่ได้ · แต่รัดกุมกับตัวเองไม่ต้องขอใคร (P7 เสนอ)

### 3.6 ⏳ **ยังโตอยู่** — ท่าโพรบที่แก้ไฟล์ในทรีร่วมแล้วคืนสภาพ (P3 เสนอ · แล้ว P3 หักมันเองในรอบถัดมา)

ท่า: ก๊อปไฟล์ไปนอกทรี → แก้ → รัน `tsc` → **คืนจากสำเนา ไม่ใช่ `git checkout`** (ซึ่งกติกาห้ามอยู่แล้ว)
🔴 **รอบสอง P3 ย่อรายชื่อไฟล์เป็นตัวแปร แล้วมันพังเงียบ:**
```bash
FILES="a.ts b.ts c.tsx"
for f in $FILES; do cp "$f" "$S/"; done     # zsh **ไม่ word-split** → $f = ทั้งสตริง → cp ล้ม
                                            # → restore() ไม่ถูกนิยาม → trap ไม่มีอะไรให้เรียก
```
· ทรีค้างสภาพโพรบ 4 ไฟล์ · **รอดเพราะบังเอิญมีสำเนาจากโพรบรอบก่อน ไม่ใช่เพราะ `trap`**
· ⚠️ **ใน `bash` โค้ดนี้ทำงานถูก** — ท่าล้มเพราะ *ความต่างของเชลล์* ไม่ใช่เพราะตรรกะผิด
· 📌 **P1 เจอกับดักเดียวกันในเซสชันเดียวกันวันนี้** (`PSQL="psql -h …"` แล้วเรียก `$PSQL` → `command not found`) — **สองครั้ง คนละคน วันเดียว เชลล์เดียวกัน**

**ถ้าจะยกเป็นท่ามาตรฐาน ต้องยกพร้อมสามข้อนี้ (P3 กำหนด):**
① **เขียนรายชื่อไฟล์เป็น literal ในลูป ห้ามใส่ตัวแปร** — ตรวจด้วยตาได้ ไม่ต้องรู้กฎ word-split ของเชลล์
② **หลัง `cp` สำรอง ให้ `ls` แล้วยืนยันจำนวนไฟล์ก่อนเริ่มแก้** — สำรองไม่สำเร็จต้องรู้ *ก่อน* แก้
③ `trap` ยังมี **แต่ห้ามพึ่งเป็นชั้นเดียว** — มันพึ่งฟังก์ชันที่อาจไม่ถูกนิยาม
