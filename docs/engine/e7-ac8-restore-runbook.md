## 4. ทำไมขั้นนี้อันตราย และท่าที่ทำให้ "พิมพ์ผิด" ไม่พอที่จะพัง

ความกลัวที่ถูกต้อง: **พิมพ์ connection string ผิด → เขียนทับฐานทริปจริง** (ทริปจริง 11–21 ต.ค.)

ท่าที่ทีมนี้ใช้ได้ผลมาแล้ว (`D72` · worktree) คือ ***เอาค่าที่ผิดได้ออกจากขั้นตอน* ไม่ใช่ *เตือนให้ระวัง***
เอามาใช้ที่นี่ได้ 3 ชั้น เรียงจากแข็งแรงที่สุด:

| ชั้น | กลไก | ทำไมมันแข็งแรง |
|---|---|---|
| **1** | **restore ลงเครื่องก่อน** | **ไม่มีปลายทางบนเน็ตให้พิมพ์ผิดตั้งแต่แรก** — ความพลาดชนิดนี้*ไม่มีอยู่* ไม่ใช่*ถูกกันไว้* |
| **2** | **ปลายทางต้องว่าง ไม่ว่างให้หยุด** | ฐานจริงมี 14 ตาราง/670+ แถว · โปรเจกต์ใหม่มี 0 → **ต่อให้พิมพ์ผิดตรงเป๊ะก็เขียนไม่ลง** |
| **3** | **ตัวแปรเดียว ตั้งครั้งเดียว ห้าม re-derive** | ด่านกับคำสั่งเขียนต้องชี้ที่เดียวกัน — ถ้าอ่านค่าใหม่ระหว่างทาง ด่านจะตรวจคนละฐานกับที่เขียน |

🔴 **ห้ามพิมพ์ ref ของฐานจริงลงในคำสั่งไหนเลย แม้แต่ใน `if` ที่ตั้งใจจะกันมัน**
ด่านต้องเขียนแบบ **ยืนยันว่าใช่ปลายทางที่ตั้งใจ** ไม่ใช่ **ยืนยันว่าไม่ใช่ฐานจริง**
— รายการ "ไม่ใช่ X" ลืมสมาชิกได้เสมอ · "ต้องเป็น Y เท่านั้น" ลืมไม่ได้ตามนิยาม

### 5A. restore ลงเครื่อง — ✅ **ทำแล้วสำเร็จ 28 ส.ค. 2026 · คำถาม ① ตอบแล้ว**

> 🔴 **ขั้นตอนฉบับแรกของหัวข้อนี้ (`brew services start` + `createdb -h 127.0.0.1`) ใช้ไม่ได้ตามตัวอักษร**
> ล้ม **5 ด่านติดกัน** กว่าจะขึ้น · ข้างล่างคือลำดับที่ผ่านจริง ไม่ใช่ที่คิดว่าจะผ่าน

```bash
brew install postgresql@17      # libpq ที่มีอยู่ให้ initdb/pg_ctl มา แต่ **ไม่มีตัวเซิร์ฟเวอร์ postgres**
```

```bash
# keg-only → binary ฝังพาธ share/lib ไว้ที่ตำแหน่ง linked ซึ่งไม่มี · ต้องต่อ symlink 2 ใบ
ln -sfn /opt/homebrew/Cellar/postgresql@17/17.11/share/postgresql /opt/homebrew/share/postgresql@17
ln -sfn /opt/homebrew/Cellar/postgresql@17/17.11/lib/postgresql   /opt/homebrew/lib/postgresql@17
```

```bash
# คลัสเตอร์ชั่วคราว — ไม่ใช้ brew services (ไม่อยากทิ้ง launch agent ไว้ในเครื่อง)
PG=/opt/homebrew/opt/postgresql@17/bin
D=<scratchpad>/pgdata
export LC_ALL=C LANG=C          # 🔴 ไม่ตั้ง = "postmaster became multithreaded during startup"
"$PG/initdb" -D "$D" --encoding=UTF8 --locale=C -U postgres
"$PG/pg_ctl" -D "$D" -l "$D/../pg.log" -o "-p 55432 -h 127.0.0.1" start
```

> ⚠️ **unix socket ใน scratchpad ใช้ไม่ได้** — พาธยาวเกิน 103 ไบต์ · จึงใช้ TCP 127.0.0.1:55432

```bash
# role ที่สคีมาอ้างถึง — **5 ตัว ไม่ใช่ 4**
"$PG/psql" -h 127.0.0.1 -p 55432 -U postgres -d postgres -c \
  "create role anon nologin; create role authenticated nologin;
   create role service_role nologin; create role supabase_admin nologin;"
```

> 🔴 **`supabase_admin` เกือบหลุด** — `grep "(TO|OWNER TO|FROM) role"` รอบแรกไม่เจอ เพราะมันอยู่ในรูป
> `ALTER DEFAULT PRIVILEGES **FOR ROLE** supabase_admin` (บรรทัด 1024) · **ตัวเลข/รายชื่อจาก `grep` เป็นเบาะแส ไม่ใช่จำนวน**

```bash
"$PG/psql" -h 127.0.0.1 -p 55432 -U postgres -d postgres -c "create database trip_restore_test;"
# dump มี CREATE SCHEMA public → ต้องลบของเดิมออกก่อน
"$PG/psql" -h 127.0.0.1 -p 55432 -U postgres -d trip_restore_test -c "drop schema public cascade;"
```

### 5B. restore ขึ้นโปรเจกต์ที่ 2 — ตอบคำถาม ② · หลังตัดสินโควตาแล้วเท่านั้น

1. เปิด org ใหม่ + โปรเจกต์ใหม่บนแดชบอร์ด (ผู้ใช้กดเอง)
2. คัดลอก connection string ของโปรเจกต์ **ใหม่** มา
3. รันสคริปต์ข้างล่าง — มันจะ **ปฏิเสธที่จะเขียนถ้าปลายทางไม่ว่าง**

```bash
cat > /tmp/restore-guarded.sh <<'SH'
#!/bin/bash
set -euo pipefail
CONN="$1"                      # ตั้งครั้งเดียว · ทุกคำสั่งข้างล่างใช้ตัวนี้ · ห้ามอ่านค่าใหม่
echo "ปลายทาง: $(psql "$CONN" -tAc "select current_database()||' @ '||inet_server_addr()")"
N=$(psql "$CONN" -tAc "select count(*) from pg_tables where schemaname='public'")
echo "ตารางใน public ของปลายทาง: $N"
if [ "$N" != "0" ]; then
  echo "หยุด: ปลายทางไม่ว่าง ($N ตาราง) — โปรเจกต์ใหม่ต้องมี 0"
  exit 1
fi
read -rp "ยืนยันว่านี่คือโปรเจกต์ใหม่ที่เพิ่งสร้าง? พิมพ์ yes: " OK
[ "$OK" = "yes" ] || { echo "ยกเลิก"; exit 1; }
psql "$CONN" -v ON_ERROR_STOP=1 --single-transaction -f /Users/park/trip-schema.sql
psql "$CONN" -v ON_ERROR_STOP=1 --single-transaction -f /Users/park/trip-data.sql
SH
chmod +x /tmp/restore-guarded.sh
```

```bash
/tmp/restore-guarded.sh "<connection string ของโปรเจกต์ใหม่>"
```

ต่อให้วางผิดสายเป๊ะ ๆ สคริปต์ก็ออกก่อนถึงคำสั่งเขียน
