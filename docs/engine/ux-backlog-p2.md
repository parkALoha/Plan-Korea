# งาน UX/UI ที่ค้างอยู่ฝั่งแพลตฟอร์ม — ส่งต่อให้ P2

> **เขียนโดย P1 · 4 ก.ย. 2026** ตามที่ผู้ใช้สั่งให้จดไว้ ตอนมอบงาน UX/UI ใหม่ให้ P2 ทำเอง
> 🔴 **นี่คือ *ของที่ฝั่งข้อมูลเจอแล้วส่งต่อ* ไม่ใช่ลำดับความสำคัญ** — P2 จัดลำดับเอง
> · ทุกข้อมี `ไฟล์:บรรทัด` ให้ตรวจเอง **อย่าเชื่อสรุปในนี้โดยไม่เปิดต้นทาง**
>   (ทีมนี้พลาดเรื่องนี้มาแล้ว 3 ครั้งในวันเดียว — รายการที่ส่งต่อกันมาล้าเร็วกว่าที่ใครคาด)

## ① หมวด `sight` — คลังมี UI ไม่รู้จัก · กระทบ ~20% ของสถานที่แนะนำทั้งหมด

**สภาพ:** `data/places.ts:108` นิยาม 10 หมวด —
`culture · nature · beach · market · cafe · nightlife · viewpoint · shopping · restaurant · transport`
**`sight` ไม่อยู่ในนั้น** · ตัวนำเข้าคลังของผม (`scripts/catalog-suggest.py`) ใช้ `sight` เป็น *ค่าตกกลับ*
เมื่อ Google ไม่ให้ type ที่แมปได้ → แถวจำนวนมากได้ `sight` ไป

**สิ่งที่ผู้ใช้เห็นวันนี้:** `categoryMetaOf()` (`components/categoryMeta.ts:38`) ตกกลับไปที่
`UNSET_CATEGORY_META` = 📍 สีเทา ป้าย *"อื่น ๆ"*
· ✅ **การ์ดไม่หาย** — `PlaceSidebar.tsx:210` มีด่านกันไว้ตรง ๆ แล้วว่าหมวดนอก `CATEGORY_ORDER` ต้องไม่หายเงียบ
· 🔴 **แต่มันไปกองรวมในถังเทาถังเดียว** ⇒ ตัวกรองตามหมวดใช้กับของกองนั้นไม่ได้เลย

**ทำไมเป็นงานของ P2 ไม่ใช่ของฝั่งข้อมูล:** คำถามจริงคือ ***"นักเดินทางอยากกรองด้วยหมวดอะไร"***
ไม่ใช่ *"Google เรียกที่นี่ว่าอะไร"* · P2 ตัดสินชุดหมวด แล้วฝั่งข้อมูล (P5/P1) backfill ตาม
· ทางเลือกที่เห็น: **(ก)** เพิ่ม `sight` เป็นหมวดที่ 11 (พร้อม emoji/สี/ป้าย) ·
  **(ข)** ยุบเข้าหมวดเดิมทีละแถว · **(ค)** แยกเป็นหมวดย่อยใหม่หลายตัว
· 🔴 **ถ้าเลือก (ก) `CATEGORY_COLOR` ต้องเป็นเลขฐานสิบหกตรง ๆ ห้ามใช้ `var(--…)`** —
  เหตุผลอยู่ที่ `components/categoryMeta.ts:7-16` (Google Maps `fillColor` ไม่แปล custom property
  และ `PlaceThumb.tsx` ต่อสตริง `` `${color}22` ``) · **ข้อจำกัดของผู้บริโภค ไม่ใช่รสนิยม**

📌 **ตัวเลข 20% วัดเมื่อ 4 ก.ย. ก่อน P5 เพิ่มคลังรอบใหม่ — นับใหม่ก่อนใช้ตัดสิน**

## ② `TripPlanScreen` ยุบ *"ทริปนี้ไม่มีเมือง"* กับ *"ถามไม่ได้"* เป็นค่าเดียว

**หลักฐานเขียนไว้แล้วในโค้ด — ไม่ใช่ข้อสังเกตใหม่ของผม:**
`hooks/useTripCatalogCities.ts:85-89` เขียนตรง ๆ ว่า

> เปิดทริปนี้ครั้งแรกตอนออฟไลน์ → ไม่มีอะไรในเครื่องให้ตอบ → `status: "error"`
> และ `TripPlanScreen` **ยังตกไปที่ `ITINERARY` เหมือนเดิม** เพราะมันยุบสองสภาพนี้เข้าด้วยกัน
> → **นั่นเป็นของที่ต้องแก้ที่ `components/` (โซน P2) ไม่ใช่ที่นี่**

**อาการที่ผู้ใช้เจอ:** เปิดทริปแพลตฟอร์มครั้งแรกตอนไม่มีเน็ต → เห็นข้อมูลทริปเกาหลีของเว็บเดิม
แทนที่จะเห็นข้อความว่าโหลดไม่ได้ · **ผิดแบบเงียบ ๆ ซึ่งแย่กว่าแสดง error**

**"เสร็จ" หน้าตาแบบไหน:** สามสภาพต้องแยกกันได้จากจอ — *กำลังโหลด* · *ไม่มีเมืองจริง ๆ* · *ถามไม่ได้*

## ③ 🛂 มุมมองวีซ่า/ตม. ผูกกับ **ประเทศ** — ห้ามยุบ `hk`/`mo` เข้า `cn`

`catalog_countries` มี `cn` · `hk` · `mo` เป็น **สามประเทศแยกกันโดยตั้งใจ** (migration `20260904040000`)
เหตุผล: **กฎเข้าเมืองต่างกันจริง** และแอปมีมุมมอง 🛂 ที่ผูกกับ *ประเทศ*
· 🔴 ถ้า UI จัดกลุ่มให้ดูสวย ("จีน" อันเดียวแล้วมีฮ่องกง/มาเก๊าอยู่ข้างใน) **ต้องไม่ทำให้ค่าที่ส่งเข้ามุมมอง 🛂 เปลี่ยน**
· รูปเดียวกับที่ `E4-AC3` ห้ามถาม *"ประเทศนี้คือเกาหลีไหม"* — จัดกลุ่มเพื่อ *แสดง* ได้ · เพื่อ *ตัดสิน* ไม่ได้

## ④ ผิวหน้า "แนะนำสถานที่" ออกแบบตอนคลังมี ~200 แห่ง · ตอนนี้ 900+

**สิ่งที่เปลี่ยนใต้มือ (4 ประเทศ 42 เมือง → 7 ประเทศ 51 เมือง และ P5 กำลังเพิ่มต่อ):**
· `components/PlaceSidebar.tsx` (571 บรรทัด) **ไม่มีช่องค้นหา ไม่มีการแบ่งหน้า** —
  จัดกลุ่มตามหมวดอย่างเดียว (`groupPlaceCards`, บรรทัด 214)
· เมืองยอดฮิตบางเมืองมีสถานที่ 30–50 แห่ง ⇒ เลื่อนยาวมาก และ ~20% อยู่ในถังเทา (ข้อ ①)

**คำถามออกแบบที่เป็นของ P2 จริง ๆ:** ผู้ใช้เปิด sidebar มาเพื่อ *เลือกที่จะไป* —
จะให้เขาเห็น **อะไรก่อน** เมื่อของมี 50 ชิ้น (ยอดนิยม? ใกล้ที่พัก? ยังไม่ได้ใส่ในแผน?)
· 📌 ฝั่งข้อมูลมี `google_place_id` ครบทุกแถวแล้ว → ดึงคะแนน/จำนวนรีวิวมาจัดอันดับได้ **ถ้า UI ต้องการ**
  ⚠️ **แต่จำนวนรีวิวเทียบข้ามประเทศไม่ได้** (จีนแผ่นดินใหญ่ต่ำผิดปกติเพราะ Google ถูกบล็อก —
  พระราชวังต้องห้าม 16,784 vs ปราสาทโอซาก้า 99,313) · **เรียงข้ามประเทศด้วยเลขนี้ = ผิด**

## ⑤ ของที่ P2 เคยจับได้เอง และผมอยากให้ถือต่อ

28 ส.ค. P2 เป็นคนพบว่า **`/api/engine/countries` คืน 4 ประเทศ ทั้งที่ฐานมี 7** —
เพราะ migration ที่ผมเขียนลืมตั้ง `supported = true` ⇒ **119 สถานที่มองไม่เห็นจากฝั่งผู้ใช้**
· 🎯 assert ของผมสามข้อผ่านหมด **เพราะทุกข้อถามว่า "แถวอยู่ในตารางไหม" ไม่มีข้อไหนถามว่า "ผู้ใช้เห็นไหม"**
· ⇒ **เวลาฝั่งข้อมูลบอกว่า "ลงคลังแล้ว" ให้ถามกลับเสมอว่ายิง endpoint จริงแล้วนับได้เท่าไร**
  นั่นคือคำถามที่ฝั่งข้อมูลถามตัวเองไม่ได้ตามโครงสร้าง
