## 2. ทิศของการเดาผิด — หลักที่ตัดสินค่าเริ่มต้นทั้งหมด

| เดาผิดทางไหน | ผู้ใช้เจออะไร | กู้ได้ไหม |
|---|---|---|
| เดาว่า **"ตอบได้"** แล้วผิด | เห็นเวลาเดินทางผิด **โดยไม่มีป้ายบอก** | 🔴 ไม่ |
| เดาว่า **"ตอบไม่ได้"** แล้วผิด | เห็นป้าย "(ประมาณการ)" เกินจริง | 🟡 ได้ |

→ **ประเทศที่ไม่มีในทะเบียนถือว่าทุกโหมดเป็นประมาณการ**

## 3. 🔴 "อย่ายิง" กับ "อย่าเชื่อ" เป็นคนละคำถาม (P2 จับได้ก่อนผมทำพัง)

ผมสั่งให้ P2 เอา `hasRealTravelTime()` ไปแทน `isTravelTimeReal`
**เขาหยุดแล้วถามก่อน** เพราะ `isTravelTimeReal` มาจาก **ผลจริงที่ยิง Google Routes ไปแล้ว
ต่อคู่ `from→to→mode`** ซึ่ง **แม่นกว่าค่าที่ทะเบียนคาดไว้**
· ถ้าทำตามที่ผมสั่ง **ญี่ปุ่นที่ Google ตอบ `DRIVE` ได้จริง จะโดนติดป้าย "(ประมาณการ)"
  บนตัวเลขที่ถูกต้อง** — ตรงข้ามกับเจตนาที่ผมเขียนไว้ในไฟล์เดียวกันนั้นเอง

| คำถาม | ใครตอบ |
|---|---|
| *"ควรยิง API ไหม"* | `shouldSkipTravelApi()` — ทะเบียน |
| *"ตัวเลขนี้จริงหรือประมาณ"* | `isTravelTimeReal` — **ผลจริงที่ยิงมาแล้ว** |

🔴 **และ `shouldSkipTravelApi` ต้องไม่ใช่ `!hasRealTravelTime()`**
`hasRealTravelTime` คืน `false` กับสองกรณีที่ต่างกัน: *"รู้แน่ว่าไม่มี"* (`kr/DRIVE`)
กับ *"ยังไม่รู้อะไรเลย"* (`jp/DRIVE`)
→ ใช้ตัวเดียวกันกรอง = **ประเทศที่ไม่รู้จักจะไม่ถูกยิงตลอดกาล → ไม่มีวันรู้ความจริง
เพราะเราไม่เคยถาม** → ทะเบียนจะ "ถูก" ตลอดไปโดยไม่มีใครท้าทายได้

## 4. ✅ ทดลองจริง: เพิ่มญี่ปุ่นโดยไม่แก้โค้ดสักบรรทัด (`E4-AC1`)

**ทำบน engine-dev · 27 ส.ค. 2026 · แก้เฉพาะ *ข้อมูล***
```
POST catalog_countries  {"id":"jp","name_th":"ญี่ปุ่น",…}     → 201
POST catalog_cities     {"country_id":"jp","legacy_slug":"tokyo",…} → สร้างแล้ว
```
**โค้ดตอบสนองทันทีโดยไม่มีใครแก้อะไร:**
```
mapProvidersFor("jp")           → ["google"]        ใช้งานได้ ไม่ใช่ปุ่มหาย
hasRealTravelTime("jp","TRANSIT") → false           ติดป้าย "(ประมาณการ)"
shouldSkipTravelApi("jp","DRIVE") → false           ยังยิง เพื่อไปรู้ความจริง

เทียบเกาหลี:
mapProvidersFor("kr")           → ["naver","kakao","google"]
shouldSkipTravelApi("kr","DRIVE") → true            ข้าม ประหยัด quota
```

### 🔴 แต่ **ยังปิด `E4-AC1` ไม่ได้** และเหตุผลต้องเขียนให้ชัด
สิ่งที่พิสูจน์แล้ว: **ชั้นข้อมูลกับทะเบียนรับประเทศใหม่ได้โดยไม่แก้โค้ด**
สิ่งที่ **ยังไม่ได้พิสูจน์**:
1. 🔴 **เปิดทริปญี่ปุ่นดูด้วยตาไม่ได้** — ยังไม่มี `/trip/[tripId]` (`E5` · P3 กำลังทำ)
   **`E5` บล็อก `E4-AC1` อยู่** และไม่มีใครเขียนความสัมพันธ์นี้ไว้จนถึงวันนี้
2. 🔴 **UI ยังใช้ `countryOfCity()` ที่ตายตัว 2 ประเทศ** — `country` จริงจาก DAL
   มาถึงครึ่งทาง (route ส่งแล้ว · hook ยังไม่ส่งต่อ เพราะ P3 ถืออยู่)
3. **ยังไม่มีใครไล่ว่ามีอีกกี่จุดที่สมมติเกาหลีเงียบ ๆ** — มอบ P2 แล้ว
   (สกุลเงิน · เบอร์ฉุกเฉิน · เขตเวลา · ชื่อผู้ให้บริการที่ฝังตรง)
