# `E7-AC1` ซ้อมบนโปรเจกต์ที่สองไม่ได้ — **ด่านกันรันผิดโปรเจกต์ล็อกไว้ที่ `engine-dev` ใบเดียว**

เขียน 2 ก.ย. 2026 (ดึก) · P1 · **พบตอนลงมือทำ `E7` จริงบนโปรเจกต์ซ้อมที่ผู้ใช้เพิ่งสร้าง**

## ✅ สิ่งที่สำเร็จแล้วคืนนี้ — `E7-AC8②`

```
engine-e7-rehearsal (lfpqdonetcsavaxowcic)
  14 ตาราง · 670 แถว · diff กับสำเนาแช่แข็ง = ว่าง
```

**ทางที่ใช้ — ไม่ต้องใช้รหัสฐานเลยสักครั้ง:**
1. `supabase db query --linked` → Management API · ใช้สิทธิ์ที่ CLI ล็อกอินไว้แล้ว
2. แต่ API รับ `COPY … FROM stdin` และคำสั่งของ `psql` (`\restrict`) ไม่ได้
   → **restore ลงคลัสเตอร์ชั่วคราวในเครื่องก่อน** (ขั้น 5A ของ `e7-ac8-restore-runbook.md`)
   → `pg_dump --inserts` → ได้ SQL ที่ API รันได้
3. ถอด `ALTER DEFAULT PRIVILEGES` 24 บรรทัด (role ของ API ทำไม่ได้)
   · **ยืนยันก่อนถอดว่าปลายทางมีสถานะเดียวกันอยู่แล้ว: `public` 6 รายการ เนื้อตรงกันทุกตัว**

**ด่านกันยิงผิดโปรเจกต์ที่ใช้จริง:**
```
ซ้อม        public tables = 0
engine-dev  public tables = 27
```
→ ถ้าเผลอชี้ผิด สคริปต์หยุด · **เป็นตัวเลขที่ต่างกันจริง ไม่ใช่ความระวัง**

## 🔴 ตัวบล็อกที่พบ — และมันบล็อก `E7-AC1` ทั้งข้อ

`E7-AC1` เขียนว่า:
> สคริปต์ migrate รันจบโดยไม่มี error **บนโปรเจกต์ซ้อม** ที่ restore มาจากสำเนาแช่แข็ง

แต่ก่อนจะรันสคริปต์ `E7` ได้ **โปรเจกต์ซ้อมต้องมีสคีมาแพลตฟอร์มก่อน** (สคริปต์ย้ายข้อมูล *จาก* `legacy.*` *เข้า* ตารางแพลตฟอร์ม)
· วิธีเดียวที่มีคือรัน migration ทั้ง 93 ไฟล์

### และ migration ทุกไฟล์ปฏิเสธที่จะรันบนโปรเจกต์อื่น

```sql
-- อยู่ใน 92 จาก 93 ไฟล์ · คัดลอกทั้งก้อน ไม่ใช่เรียกฟังก์ชัน
if not exists (
  select 1 from app.project_identity
   where name = 'plan-korea-platform'
     and ref  = 'pmvxwcimjebogjfimzqy'      -- ← engine-dev เท่านั้น
     and environment = 'dev'
) then raise exception 'ผิดโปรเจกต์: …'; end if;
```

**และตัวบูตสแตรปก็ hardcode เหมือนกัน:**
```sql
-- 20260824220618_project_identity_guard.sql
insert into app.project_identity (name, ref, environment)
values ('plan-korea-platform', 'pmvxwcimjebogjfimzqy', 'dev');

environment text not null check (environment in ('dev','staging','prod'))   -- ไม่มี 'rehearsal'
```

🎯 **`E7-AC1` สั่งให้ซ้อมบนโปรเจกต์อื่น · migration สั่งว่าห้ามรันบนโปรเจกต์อื่น — สองข้อนี้ขัดกันโดยตรง**

# 🔴 ตัวบล็อกที่สอง — และมันใหญ่กว่าตัวแรกมาก (วัดเมื่อ 3 ก.ย. 2026 เช้า)

**ผมลองทางที่สาม: ไม่แตะด่านเลย · ประกอบสคีมาในคลัสเตอร์ทิ้งในเครื่อง แล้วย้ายเฉพาะ `public` ขึ้นโปรเจกต์ซ้อม**
เหตุผลที่ทางนี้ควรได้: **สคริปต์ `E7` ทั้ง 11 ไฟล์ไม่มีด่านกันรันผิดโปรเจกต์เลยสักไฟล์** → สิ่งที่ต้องขึ้นไปคือ *สคีมา* ไม่ใช่ *migration*

## ผลที่วัดได้ — ไล่ทีละขั้น ไม่ได้เดา
```
ฐานเปล่า                                   →  18/93   (ขาด schema auth)
+ สตับ auth/storage/extensions              →  31/93   (สตับ opclass ผมเองไม่ครบ)
+ ติดตั้ง pg_trgm/unaccent ลง extensions     →  38/93   (ขาด supabase_migrations)
+ สแกนหา schema ภายนอก *ทั้งหมด* ทีเดียว     →  60/93   (9 วัตถุ ครบ)
+ หว่านข้อมูลจำลอง (trip/day/plan/stop)      →  **65/93**
```

## 🔴 และตัวที่ล้มที่เหลือ **ไม่ใช่เรื่องสตับ** — มันคือ migration ที่เป็น *เทสต์สด*
```
20260826172600_e2_rank_shape_real_negative_test   ต้องมีแถว trip_stops อยู่ก่อน
20260826182000_e3_probe_trigger_role_under_definer ต้องมีข้อมูล · และสร้าง app.role_probe ที่ไฟล์ถัดไปต้องใช้
20260826210000_e3_read_only_deny_by_user_context   ต้องมี role/JWT จริง — `auth.uid()` ที่คืน null ไม่พอ
```
🎯 **`migration` ชุดนี้ไม่ใช่ *ตัวสร้างสคีมา* — มันคือสคีมาที่ *สลับกับเทสต์สด* ซึ่งสมมติว่ารันบนโปรเจกต์ Supabase ที่มีข้อมูลอยู่แล้ว**
· ⚠️ **เล่นซ้ำเพื่อสร้างฐานใหม่จึงทำไม่ได้ตามนิยาม** ไม่ว่าจะแก้ด่านโปรเจกต์หรือไม่

## 🔴 ผลที่กระทบมากกว่า `E7` — **`E9` ชนกำแพงเดียวกัน**
`E9` คือการสร้างโปรเจกต์ **prod** แล้วย้ายข้อมูลจริงขึ้นไป · **ถ้าสร้างสคีมาจาก migration ไม่ได้ prod ก็สร้างไม่ได้ด้วยวิธีนี้**
· 📌 วันนี้ไม่มีใครเจอเพราะ `engine-dev` ถูกสร้าง *ทีละ migration ตามเวลาจริง* — **ไม่เคยมีใครเล่นซ้ำทั้งชุดตั้งแต่ต้น**
