**ทางที่ใช้ — ไม่ต้องใช้รหัสฐานเลยสักครั้ง:**
1. `supabase db query --linked` → Management API · ใช้สิทธิ์ที่ CLI ล็อกอินไว้แล้ว
2. แต่ API รับ `COPY … FROM stdin` และคำสั่งของ `psql` (`\restrict`) ไม่ได้
   → **restore ลงคลัสเตอร์ชั่วคราวในเครื่องก่อน** (ขั้น 5A ของ `e7-ac8-restore-runbook.md`)
   → `pg_dump --inserts` → ได้ SQL ที่ API รันได้
3. ถอด `ALTER DEFAULT PRIVILEGES` 24 บรรทัด (role ของ API ทำไม่ได้)
   · **ยืนยันก่อนถอดว่าปลายทางมีสถานะเดียวกันอยู่แล้ว: `public` 6 รายการ เนื้อตรงกันทุกตัว**

**ด่านกันยิงผิดโปรเจกต์ที่ใช้จริง:**
```

```
→ ถ้าเผลอชี้ผิด สคริปต์หยุด · **เป็นตัวเลขที่ต่างกันจริง ไม่ใช่ความระวัง**

## 🔴 ทำไมผมสรุปผิด — **สนามที่ผมสร้างเองขาดคุณสมบัติ ไม่ใช่สายพานที่พัง**
ผมสร้างสนามขึ้นมา*ใหม่*แทนที่จะรันสคริปต์ที่มีอยู่ · สนามของผมขาด 3 อย่าง:
```
①  รันเป็น superuser        →  superuser **ข้าม RLS**  →  ด่านของ migration อ่านว่าพัง
②  ไม่มี auth.jwt()          →  migration ใบที่พึ่งมันล้ม
③  ไม่มี hook สองจุด         →  ใบที่ต้องมี trip_stops / ต้องลบ bucket ก่อน ล้ม
```
🎯 ***สนามที่ขาดคุณสมบัติ ให้ "แดงปลอม" ที่อ่านเหมือนคุณสมบัติของโค้ด***
· ⚠️ **นี่คือฝาแฝดกลับด้านของ *"เขียวหลอกเชิงสภาพแวดล้อม"* ที่อยู่ใน `TEAM.md §3.4` อยู่แล้ว** —
  ใบนั้นบอกว่า *ก่อนเชื่อผลลบ ถามว่าสภาพที่รันมีคุณสมบัติที่บั๊กต้องใช้ครบไหม* · **ผมไม่ได้ถาม**
· 🔴 **และตัวที่กัดที่สุด: สคริปต์ที่ถูกต้องผมเขียนเองเมื่อ ~6 ชั่วโมงก่อน (`73c10cc`)**
  ผมไม่ได้ลืมว่ามันมี — ผมจำ *ข้อความ commit ของมัน* ได้ (*"สายพานรันบนฐานเปล่าไม่ได้"*) แล้วเชื่อสรุปนั้นต่อ
  **โดยไม่รันซ้ำ** · 🎯 ***ข้อสรุปเก่าของตัวเอง ถูกเชื่อง่ายกว่าข้อสรุปของคนอื่น เพราะไม่รู้สึกว่าเป็นการอ้างแหล่ง***
