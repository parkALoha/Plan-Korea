### 🔴 dev DB — เปลี่ยนจาก Docker เป็น Supabase คลาวด์ในองค์กรใหม่

**ยืนยันจากหน้าราคาจริง (17 ส.ค. 2026):** free plan = **"Limit of 2 active projects"** ต่อ**องค์กร**
· ไม่มี automatic backup และไม่มี PITR เลย · Pro เริ่ม $25/เดือน
ตอนนี้องค์กรปัจจุบันมี `plan-korea` + `mu-phone` = **ครบ 2 พอดี**

**ทางที่เลือก: สร้าง organization ใหม่ → ได้อีก 2 โปรเจกต์ฟรี** (staging + prod ของแพลตฟอร์ม)
**เหตุผลที่ดีกว่า Docker ไม่ใช่แค่ประหยัดแรงติดตั้ง:**
- P6 ระบุว่า local **ทดสอบ OAuth provider ภายนอกกับ Supavisor pooler ไม่ได้** ซึ่งเป็น 2 จุดที่ "บนเครื่องผ่าน ขึ้นจริงพัง" บ่อยที่สุด
- **องค์กรแยก = ขอบเขตแข็งกว่าโฟลเดอร์แยก** — คนละ org ไปเลย ไม่มีทางกดผิดโปรเจกต์ข้ามไปโดน DB ทริป
- ไม่กิน RAM ~4 GB บนเครื่องที่ต้องรัน `next dev` + เบราว์เซอร์อยู่แล้ว

⚠️ **ข้อแลก:** free tier หลับเมื่อไม่มีทราฟฟิก 7 วัน (เหตุผลเดียวกับที่ทริปต้องมี cron `keep-alive`) — staging ต้องมีกลไกเดียวกัน
⚠️ **ไม่มี backup/PITR บน free** — ตอนขึ้น prod จริงของแพลตฟอร์มต้องขยับเป็น Pro ตามที่ P6 ประเมินไว้

### 10 ข้อที่ขวางการเป็นแพลตฟอร์ม (ตรวจจากโค้ดจริง 17 ส.ค. 2026)

ไม่มี identity เลย · **RLS 53 policy เป็น `using (true)` ทั้งหมด ไม่มี `auth.uid()` สักที่**
· ด่าน PIN กันแค่ Next ไม่กัน Supabase · `day_id` เป็นสตริงตายตัว `d0`–`d10` **ไม่มี `trip_id` ที่ไหนเลยใน 14 ตาราง**
· tenancy key ไม่สม่ำเสมอ (4 ตารางลอย) · ประเทศอยู่ใน TS type ไม่ใช่ข้อมูล · คลังสถานที่อยู่ในไฟล์ TS 71 KB
· **ไม่มี server-side data fetching เลยสักจุด — แตะตาราง Supabase 67 จุดใน 13 ไฟล์ยิงจาก browser**
  (10 hooks ถือ 60 จาก 67 · component ศูนย์) · Storage `booking-files` เป็น public ไฟล์ตั๋วเปิดได้ด้วย URL ล้วน
· `next.config.ts` ว่างเปล่าทั้งไฟล์ · เทสต์ครอบเฉพาะ pure function
→ รายละเอียดเต็มพร้อมเหตุผลที่ [`docs/engine/README.md`](docs/engine/README.md)
